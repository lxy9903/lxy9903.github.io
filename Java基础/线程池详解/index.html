线程池详解

[TOC]

一、ThreadPoolExecutor 是什么？

ThreadPoolExecutor 通过 ctl 原子变量统一管理状态和线程数，通过 workQueue 决定扩容策略，通过 Worker 封装真实线程执行，通过 execute 驱动任务流转，通过 shutdown 保障有序关闭，通过拒绝策略保证系统在极限压力下不崩溃。

这些字段全部都在：

这是 JDK 并发包的核心类。

二、核心字段总览

字段 作用一句话
ctl 线程池状态 + 线程数量（最核心）
corePoolSize 核心线程数
maximumPoolSize 最大线程数
keepAliveTime 非核心线程空闲回收时间
workQueue 任务队列
workers 线程池中真实存在的线程集合
mainLock 保护 workers 集合
handler 拒绝策略

四、corePoolSize / maximumPoolSize / keepAliveTime

1️⃣ corePoolSize

  • 最少保持的线程数
  • 即使空闲，也不会回收（除非 allowCoreThreadTimeOut）

2️⃣ maximumPoolSize

  • 线程池能创建的最大线程
  • 只有当：
    • core 满了
    • 队列满了才会尝试创建

3️⃣ keepAliveTime

  • 非核心线程空闲多久后回收
  • 如果开启：

核心线程也会被回收

八、shutdown / shutdownNow / stop

1️⃣ shutdown()

  • 状态：RUNNING → SHUTDOWN
  • 不接收新任务
  • 执行完队列任务

2️⃣ shutdownNow()

  • 状态：RUNNING → STOP
  • 中断所有线程
  • 返回未执行任务

3️⃣ stop（已废弃）

  • 直接杀线程
  • 数据不一致
  • 禁止使用

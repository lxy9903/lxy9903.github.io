倒排索引

1. 什么是倒排索引？

倒排索引是搜索引擎（如 Elasticsearch、Solr）、信息检索系统的核心数据结构。

它从 词 → 文档列表 的方向进行索引，而不是传统数据库那样从 文档 → 内容。

📌 正排索引（forward index）
DocID → 文档内容

📌 倒排索引（inverted index）
Term → 包含该词的文档列表（Posting List）

2. 倒排索引的数据结构

倒排索引一般包含两个核心组件：

1）词典（Dictionary / Term Index）

保存所有出现过的 term（关键词），通常排序、压缩并带跳表、前缀树等优化。

2）倒排表（Posting List）

记录每个 term 在哪些文档中出现：

Posting List 由多个 Posting 组成，每个 Posting 包含：

字段 含义
DocID 文档编号
TF（Term Frequency） 在该文档中出现几次
Positions 出现的位置（用于短语检索）
Payload 如权重、字段等

3. 倒排索引的构建流程

构建过程类似搜索引擎的“建索引”：

Step 1：读取文档

读取文档内容（网页、文件、数据库记录…）。

Step 2：分词 Tokenization

例如

“Java concurrency programming”
分成：[“Java”, “concurrency”, “programming”]

支持中文分词（如 IKAnalyzer）：

“我喜欢学习算法”
分成 [“我”, “喜欢”, “学习”, “算法”]

Step 3：标准化 Normalization

如：小写、去停用词、词干提取等。

Step 4：生成 Posting

对每个 term 记录：

  • 出现在哪些文档？
  • 出现了多少次？
  • 在文档的哪些位置？

Step 5：对 Posting List 排序并压缩

排序 DocID
使用差值编码（Delta-Encoding）
可选使用位级压缩（例如 VB 编码、PForDelta）

4. 倒排索引的查询原理

假设输入查询词：

“java concurrency”

系统会：

  1. 分词，得到 [“java”, “concurrency”]
  2. 在 Dictionary 查每个 term 的 Posting List
  3. 对多个 Posting List 求交集（AND 查询）
  4. 根据 TF-IDF、BM25 排序
  5. 返回结果

5. 为什么倒排索引适合全文检索？

✔ 查询极快（O(logN)）

因为 Term 可以用 B+Tree / Hash / FST（前缀树）快速检索。

✔ Posting List 可以跳跃查找

跳表、Skip List，可支持快速 AND/OR 操作。

✔ 压缩好、占空间小

差值编码、位图、分块，提高磁盘命中率。

6. 倒排索引的应用场景

场景 倒排索引作用
Elasticsearch 搜索 核心数据结构
搜索引擎（Google/Bing） Web 索引
日志搜索（ELK） 索引日志字段
数据库全文检索 (MySQL FULLTEXT) 使用倒排索引实现
推荐系统关键词匹配 加速文本召回

7. 倒排索引与传统数据库索引对比

对比项 倒排索引 B+Tree 索引
适合场景 全文搜索、关键词查询 结构化字段过滤、范围查询
结构 Term → Docs Key → Row
查询速度 高频词需跳跃优化 范围查询更快
空间占用 大，需要压缩 较小

8. 重点关注

❓ 为什么 Elasticsearch 使用倒排索引？

因为：

  • 文本搜索需要按词查文档
  • 倒排索引可快速合并多个关键词的文档列表
  • 支持 BM25、TF-IDF 排序
  • 支持短语检索、模糊匹配

❓ 倒排索引如何优化？

  • 前缀压缩（FST）
  • Posting List 差值编码
  • 跳跃表加速交集
  • 分片 + 副本 + Segment 合并

❓ 倒排索引为什么不用于频繁更新？

因为更新一个 term 会影响多个 Posting List，成本大。
所以 ES 使用 LUCENE Segment + Merge append-only 写入模式。

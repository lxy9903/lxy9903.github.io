Oracle主从备份

Oracle Data Guard（物理备库） + 最大可用模式 + Fast-Start Failover（FSFO）

一、Data Guard 是什么？

Data Guard 用于：

  • 实时传输主库 redo log 到备库
  • 备库将 redo 实时 apply
  • 保持两个数据库一致

重点：备库不能自主写数据，只能回放主库的 redo。

✔ 主库：能读能写
✔ 备库：只写（redo apply），不能读
✔ 实时同步

二、选择“物理备库（Physical Standby）”而不是逻辑备库

Oracle 有两种备库：

类型 同步方式 是否读写 作用
物理备库 Physical Standby Redo 二进制级别 apply 不能读（除非 Active Data Guard） 与主库完全一致，最快最可靠
逻辑备库 Logical Standby Redo 解析成 SQL 后执行 可以读写 稍慢，有延迟

三、主从同步方式：选择“最大可用模式（Maximum Availability）”

Data Guard 有三种同步模式：

1）Maximum Performance（异步）

  • 高性能但可能丢数据

2）Maximum Protection（强同步）

  • 备库挂了主库会停

3）Maximum Availability（强同步+保护模式）

  • redo 同步写入备库
  • 备库确认后主库事务才提交
  • 备库短暂不可用时主库自动转为异步，不影响服务
  • 备库恢复后自动切回同步

优点：

✔ 几乎 0 数据丢失
✔ 主库稳定（备库挂了不会阻塞）
✔ 金融、电商常用

四、秒级切换：Fast-Start Failover（FSFO）

Data Guard 支持 自动主备切换：

  • 由一个 Observer进程 持续监控主库
  • 主库故障（掉电、网络断开、崩溃等）
  • Observer 自动触发 failover
  • 备库在 1–10 秒内切换为新主库

无需人工参与。

✔ 秒级切换
✔ 数据一致
✔ 自动恢复

五、最终架构

行为说明：

  • 主库负责 读 + 写
  • 备库只做 redo apply（写）
  • Observer 监控后自动触发 failover

六、为什么 Oracle 能“只写不读 + 秒级切换”？

因为：

1）Oracle redo 是二进制级别，不经过 SQL 转换

同步速度快、可靠性强。

2）物理备库完全继承主库结构

切换几乎不需要额外操作。

3）FSFO 自动化，不依赖人工

秒级切换不是吹的，是全自动。

七、Fast-Start Failover（FSFO）自动故障切换

  • 由 Observer（观察者进程） 监控主库
  • 主库故障时自动触发 failover
  • Standby 立即升级为新的 Primary
  • 典型切换耗时 2–10 秒

为什么这么快？

1）物理备库与主库是二进制级别同步（Redo）

实时 apply，几乎无延迟。

2）Standby 数据结构与 Primary 完全一致

不需要重放 SQL、不需要构造数据。

3）failover 是自动、即时的

Observer 监控的是 TCP+心跳，与主库崩溃检测非常快。

八、对比 MySQL，有类似方案吗？

有，但没有 Oracle 完整：

MySQL 等价方案：

  • MySQL MGR（Group Replication）
  • InnoDB Cluster

但：

  • 使用 binlog event 同步，不如 Oracle redo 一致性强
  • 切换也通常要依赖 Router，而不是像 FSFO 那样自动
  • “只写不读”的逻辑也不如 Oracle 明确

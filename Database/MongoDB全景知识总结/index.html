MongoDB全景知识总结

一、MongoDB 整体架构总览

MongoDB 是文档型分布式数据库，支持高可用（ReplicaSet）和水平扩展（Sharding），底层存储默认 WiredTiger 引擎，采用 BSON（二进制 JSON）格式。

1. 整体结构分层

  • 客户端层：应用、Shell、驱动程序
  • Server 层（mongod / mongos）
    • 查询解析器
    • 优化器
    • 执行器
  • 存储引擎（WiredTiger）
    • Cache / Buffer
    • Journal 日志
    • 数据文件（.wt）
    • 索引文件（B-Tree）
  • Replica Set 副本集
  • Sharding 分片架构

二、核心组件说明

1. MongoDB Server 层

（1）查询解析器（Query Parser）

  • 解析 BSON 查询
  • 生成语法树（AST）

（2）查询优化器（Query Optimizer）

  • 比较多种执行计划
  • 根据索引、统计信息选择最佳路径
  • 与 MySQL 成本优化器类似（但更简单）

（3）执行器（Executor）

  • 负责具体 CRUD、聚合 Pipeline、索引扫描

2. 存储引擎层（WiredTiger）

WiredTiger 是 MongoDB 默认引擎，核心特性：

（1）MVCC 多版本并发控制

  • 每个文档保存时间戳
  • Reader 不阻塞 Writer
  • Writer 也不阻塞旧 Reader

（2）数据压缩（Snappy / Zstd）

  • 文档压缩
  • 索引页压缩

（3）缓存（Cache）

  • WiredTiger Cache = 内存 50%

（4）日志（Journal）

  • WAL 写前日志，保证崩溃恢复

三、MongoDB CRUD 执行流程

1. 写入流程（Insert / Update）

流程步骤：

  1. Client 发送写请求
  2. Server 解析 → 生成执行计划
  3. 调用 WiredTiger 写入缓存
  4. 写 Journal 日志（WAL）
  5. 后台线程刷新至数据文件（checkpoint）
  6. 若为副本集：Primary 写入后 → 同步 Secondary（OpLog）

2. 读取流程（Find / Aggregate）

流程步骤：

  1. 客户端发送查询
  2. Server 解析 + 优化
  3. 判断是否命中索引
  4. 若命中：B-Tree → 直接定位文档
  5. 若不命中：全 Collection Scan
  6. 从 Cache 或磁盘加载
  7. 返回给客户端

四、MongoDB 底层存储结构（WiredTiger）

0. 示例 BSON 文档

1. 数据结构层级

MongoDB → Database → Collection → Document → Field

类似 MySQL：

  • DB → Table → Row → Column

2. WiredTiger 页（Page）结构

类型 说明
internal page B-Tree 索引内部节点
leaf page 存储文档或索引记录
overflow page 大文档（>Page size）

默认页大小：16KB（与 InnoDB 相似）

3. 文档存储方式

  • BSON 二进制格式
  • 支持嵌套文档、数组
  • 字段类型在文档内部链式存储

4. B-Tree 索引结构

MongoDB 索引底层采用：

  • B-Tree / B+Tree 变体（WiredTiger B-Tree）
  • 与 MySQL InnoDB B+Tree 非常相似

特点：

  • 有序结构
  • 范围查询高效
  • 前缀压缩减少存储占用
  • 每个叶子节点存储多个 key-value 文档指针

5. 数据落盘流程

五、MongoDB 数据类型（详细版）

类型 存储大小 说明
Double 8B 双精度浮点
String 字符串长度 + UTF8 任意长度
Object 文档 递归嵌套
Array 文档数组
Binary 长度 + 数据 文件类数据
ObjectId 12B 默认主键
Boolean 1B
Date 8B 毫秒精度
Int32 4B
Int64 8B
Decimal128 16B 金融使用
Timestamp 8B 同步用

六、事务与锁机制

1. 事务（MongoDB 4.0+）

  • 支持多文档事务（Replica Set）
  • 支持分片集群事务

与 MySQL 不同：

  • MongoDB事务属于“补充性机制”，日常少用

2. 锁机制

引擎 锁粒度
WiredTiger 文档级锁（最小粒度）
MMAPv1（旧） 库级 / 集合级锁

MongoDB 并发效率显著高于旧版。

七、索引体系

1. 索引类型

类型 场景
单字段索引 name、age
复合索引 {age:1, score:-1}
唯一索引 用户名唯一
TTL 索引 过期数据删除
文本索引 搜索（倒排索引）
Geo2d / GeoSphere 地理位置

2. WiredTiger B-Tree 索引原理

与 MySQL InnoDB 类似：

  • 高度一般 2~3 层
  • 节点大小：16 KB Page
  • 前缀压缩减少键空间
  • 叶子节点存储文档或记录指针（RecordId）

不同于 InnoDB：

  • MongoDB 文档是非定长结构（BSON）
  • MongoDB 没有“聚簇索引”，数据和主键索引分离

3. 索引扫描方式（核心面试点）

  • IXSCAN：索引扫描
  • FETCH：根据 RecordId 拿文档
  • COLLSCAN：全表扫描
  • SORT：排序阶段（索引未覆盖时触发）

八、副本集（Replica Set）

1. 架构组成

  • 1 个 Primary
  • N 个 Secondary
  • Arbiter（可选）

2. Primary 写入流程

  1. 写入 Primary
  2. Primary 写 OpLog
  3. Secondary 拉取 OpLog
  4. 进行重放（applyOps）
  5. 保证最终一致性（eventual consistency）

3. 心跳机制

  • 检测节点存活
  • Primary 失败 → 自动选举

九、分片（Sharding）结构

1. 组成部分

组件 功能
Mongos 路由器
Config Server 元数据存储
Shard 数据节点（副本集）

2. 分片关键概念

  • 分片键（Shard Key）
    决定数据分布
  • Chunk
    64MB 数据分片单元
  • Balancer
    均衡数据

十、MongoDB 核心考点

  1. MongoDB 与 MySQL 区别（Schema-less、分布式、BSON）
  2. WiredTiger 存储引擎特点（MVCC、压缩、缓存）
  3. 索引结构（B-Tree）与优化方式
  4. 查询优化（IXSCAN、覆盖索引、避免排序）
  5. 副本集原理：OpLog、选举、同步
  6. 分片机制：Shard Key、Chunk、Balancer
  7. 事务模型（多文档事务）
  8. BSON 与数据类型
  9. 写入路径 / 读取路径
  10. Cache 与 Journal 工作机制

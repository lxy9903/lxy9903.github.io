MySQL底层架构

[TOC]

一、MySQL 底层架构总览

MySQL 可分为 Server 层（通用层） 和 存储引擎层（InnoDB）。

二、核心组件说明

1. MySQL Server层

模块 功能
连接器 SSL、TCP、账号密码校验、线程管理
解析器（Parser） 词法分析、语法分析生成 AST
优化器（Optimizer） 选择索引、Join 顺序、执行计划
执行器（Executor） 调用 Engine API，如“取某范围记录”

2. InnoDB 存储引擎层

模块 描述
Buffer Pool 缓存数据页、索引页、Undo 页，多数读写在内存完成
Redo Log（WAL） 顺序写，崩溃恢复，保证事务持久性
Undo Log MVCC、回滚
Doublewrite Buffer 解决页中写（partial page write）问题
Background Threads 刷盘、合并、页分裂、页回收
数据页（16KB） B+Tree 节点 / 行存储单元

3. MySQL 写入路径

4. MySQL 读取路径

三、MySQL 底层架构

1. Server 层

连接器 → 解析器 → 优化器 → 执行器

2. InnoDB 内部组件

  • Buffer Pool（核心缓存）
  • Redo Log（写前日志）
  • Undo Log（MVCC）
  • Doublewrite Buffer
  • 后台线程
  • 磁盘 Data Pages（.ibd）

3. 数据流向

  • 读路径：磁盘 → Buffer Pool
  • 写路径：
    • 内存修改（Buffer Pool）
    • 记录 Redo
    • 记录 Undo
    • 后台线程刷盘

4. 写入流程

  1. 客户端发送 SQL INSERT/UPDATE/DELETE
  2. Server 层：
    • 解析 SQL → AST
    • 优化器生成执行计划
    • Executor 调用存储引擎
  3. InnoDB 层：
    • 写入 Redo Log（顺序写，保证事务持久性）
    • 写入 Undo Log（支持回滚和 MVCC）
    • 聚簇索引（主键）叶子节点写入行数据
    • 二级索引更新：将索引值 + 主键写入二级索引页
    • 写入 Buffer Pool（页缓存）
  4. 事务提交：
    • Redo Log 刷盘
    • Buffer Pool 数据页异步落盘（Checkpoint）

5. 读取流程

  1. 客户端发送 SQL SELECT
  2. Server 层：
    • 解析 SQL → AST
    • 优化器选择访问路径（全表扫描或索引扫描）
  3. InnoDB 层：
    • 如果有 WHERE 条件可以使用索引：
      • 通过二级索引快速定位主键
      • 再通过聚簇索引根据主键读取完整行数据
    • 如果没有索引 → 全表扫描（Buffer Pool → 磁盘）
  4. Server 层返回结果给客户端

四、MySQL 数据底层存储（InnoDB）

0. 示例表

  • 主键索引（Clustered Index）= 数据存储本体
  • 二级索引（Secondary Index）=（索引列 + 主键值）组成树
  • 二级索引查数据 → 一定要回表（因为叶子节点不存整行）

1. 表空间（Tablespace）

  • 每张独立表（innodb_file_per_table=1）对应一个 .ibd 文件，例如：
  • 文件包含：
    • 数据页（存行记录）
    • 索引页（B+Tree）
    • Undo 页（MVCC 回滚版本）
    • 系统页（INODE / FSP_HDR）
    • 事务信息、段、区等元数据
  • 结构示意：
  • 每张表本质是 B+Tree Forest：
    • 主键聚簇索引一棵树
    • 每个二级索引一棵独立树

2. 段（Segment）

段是逻辑上的「索引或数据集合」。

InnoDB 一个表至少有两个段：

  1. 主键段（Clustered Index Segment）
  2. 每个二级索引一个独立段（Secondary Index Segment）

示例表包含：

  • PK 段（存储整行）
  • idx_user_id 段
  • idx_created_at 段

每个段内部以 Extent 和 Page 组成树结构。

3. 区（Extent）

Extent = 1MB = 64 页（16KB × 64）

  • InnoDB 以 “区” 为单位分配磁盘空间
  • 区内存各种类型的 Page（数据页、索引页、Undo 等）

4. 页（Page） 16KB

页 = InnoDB 数据存储的最小单位
每张表的所有行最终都被分配到「页」里。

主要页类型：

Page 类型 含义
数据页（Leaf Page） 主键 B+Tree 的叶子，存整行
索引页（Internal Page或Leaf of secondary index） B+Tree 中间节点或二级索引叶子
Undo 页 事务回滚信息
系统页 管理信息

5. 行记录（Row）存储

默认行格式：Compact / Dynamic

存储内容：

  • 主键值（必须）
  • 各列的值
  • 隐藏列：
    • trx_id（最后修改本行的事务号）
    • roll_pointer（回滚指针，指向 Undo Log）

长字段（如 TEXT、BLOB）只在页内存 前 768 字节，剩余内容放到 Off-Page。

6. B+Tree 索引存储结构

所有索引（主键、二级索引）都用 B+Tree 存储：

  • 根节点（1 页）
  • 中间节点（若干页）
  • 叶子节点（大量页）

主键索引存“整行”

示例：

二级索引只存：索引列 + 主键值（用于回表）

例：idx_user_id(user_id)

查询时流程：

  1. 在二级索引 B+Tree 找到 user_id=50 → 得到主键 id=1001
  2. 再到主键 B+Tree 找 id=1001 → 拿到整行

每一个 索引 = 一棵 B+Tree
树由 数据页（Leaf Pages） 和 非叶子页（Internal Node） 组成。

7. 示例：数据库表如何落到磁盘？

假设我们插入 200 万订单

每页大概能放：

  • 假设一条行记录约 200 字节
  • 16KB ≈ 16000字节
  • 每页 ≈ 80 行（不算额外开销）

200万行 / 80 ≈ 25,000 页
25,000页 / 64（每区的页数） ≈ 390 个 Extent

这些 Extent 属于：

  • 主键段（Clustered）
  • 用户ID二级索引段
  • created_at二级索引段

每个段都是自己独立的一棵 B+Tree。

五、MySQL 数据类型及底层存储大小

1. 数值类型及存储大小

类型 存储大小 说明
TINYINT 1B 范围 -128~127
SMALLINT 2B -32768~32767
MEDIUMINT 3B 常用于节省空间
INT 4B 常用
BIGINT 8B 金融、ID
FLOAT 4B 单精度
DOUBLE 8B 双精度
DECIMAL(M,D) 按存储位数 精确表示（用于金额）

2. 字符类型

类型 存储 特点
CHAR(n) 固定 n 字节（按编码） 适合同大小字段，如性别、状态码
VARCHAR(n) 实际长度 + 1/2 字节 节省空间
TEXT 2+ 实际内容 存放在 Overflow page（长字段）

UTF8MB4 每字符最多 4 字节。

3. 日期时间

类型 存储 范围
DATE 3B 年-月-日
TIME 3B 时分秒
DATETIME 5B（compact） 推荐
TIMESTAMP 4B 受时区影响

4. 行溢出（Overflow）

当：

  • VARCHAR 非常大
  • TEXT / BLOB
  • 数据页放不下 16KB

则会存入 Overflow Pages（溢出页），主行存一个 20 字节指针。
